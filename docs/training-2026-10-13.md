# Live Q3 data entry and onboarding handbook

Updated 14 October 2026 for onboarding in the week of 12-18 October. Participants will use the live database to enter their real Q3 2026 funding and expenditure. Q3 covers **1 July to 30 September 2026 inclusive**. Every confirmed submission contributes to live reporting. Use actual source amounts, transaction dates and references throughout.

The session combines training with supervised completion of each MDA's Q3 return. Participants leave with verified entry IDs/import receipts and a list of unresolved source-data issues. It is not a dummy-data exercise. Do not insert invented amounts, test references or October transaction dates for July-September activity.

## What users can do today

Routine data entry uses two authenticated web forms: **Funding** for money received and **Expenditure** for money spent. Each submission records one transaction. Dropdowns use controlled reference data. The signed-in user supplies the audit identity; fiscal year and quarter come from the transaction date.

Valid entries become reportable when saved to the server. There is no approval or rejection queue. Comments ask for clarification without changing reportability. Publishing a quarterly Budget Implementation Report (BIR) locks new routine entries and edits for that quarter. Admin corrections after publication use an audited amendment.

Offline form submissions can be saved in this browser's local outbox and sent on reconnection. A pending local record is not yet a server submission or part of server reports.

**Bulk file ingestion is implemented at Imports → Import entries.** It accepts CSV and XLSX transaction ledgers, provides mapping and clarification controls, flags row issues, previews totals, and inserts ready rows only when the owner confirms. Optional AI assistance (phase 2, deployed 14 October) can classify workbook sheets, suggest column mappings and suggest meanings for unmatched values; it only suggests, and nothing is applied until the user confirms. Validation and insertion remain deterministic. PDFs and loading planning/summary datasets (monthly returns, budgets, AOP, quarterly totals) are not part of this release. The separate AI assistant remains read-only.

## Prepare each MDA's real Q3 data

Bring July, August and September receipt/payment registers, actual release references and payment vouchers, the funding source for each payment, programme/category classifications, and supporting documents. Bring the 2026 approved budget and AOP for reference where applicable; those plans are not themselves cash transactions.

Before entry, the facilitator and MDA owner check existing Q3 records, source references and any historical aggregate entries. Record starting counts/totals by MDA and ledger. Assign one submission owner per source file/register, and mark which rows will be entered manually versus imported. The same transaction must not go through both paths.

Admin must verify that Q3 2026 is open for routine entry. If its BIR has already been published, use the established correction/amendment process rather than changing transaction dates or bypassing the lock. Q3 status and current live totals must be checked in the application; this handbook does not assume they are open or empty.

Check whether any Q3 totals have already been loaded from a published report. Aggregate rows can overlap detailed transactions even when voucher references differ. The importer cannot resolve that accounting overlap automatically; the Admin must reconcile it before additional detail is confirmed.

## Roles and account preparation

| Role | What to teach | What it cannot routinely do |
| --- | --- | --- |
| MDA User | Enter or import funding/expenditure for specifically assigned MDAs and permitted ledgers; view assigned data; respond to comments; edit own entries before publication; request missing reference values. | Submit for unassigned MDAs, manage reference lists, publish a BIR, or edit a locked quarter. |
| Viewer | The app's label for a reviewer. View statewide entries and reports, inspect available warnings/audit history and add comments. | Approve/reject entries, edit transactions, manage users or reference lists, or publish a BIR. |
| Admin | Manage users, roles, MDA grants, reference requests, reference data, approved budgets and AOP activities; inspect reports; make reasoned corrections; publish and amend BIRs. | Use routine edits to bypass a published-quarter lock. |
| Facility User | PHC form is scoped to assigned facilities. Confirm live write access with the Admin before allocating an entry task; implementation notes flag an unresolved database permission gap. | Use Imports, enter funding, or spend for an unassigned facility. |

Funding and expenditure permissions are separate grants. Assigning an MDA alone is not a substitute for the appropriate `funding_submitter` and/or `expenditure_submitter` grant. Test both expected menu items before handing over an account.

Each attendee needs their login email/password or accepted invitation, assigned role, correct MDA grants, an internet connection for initial sign-in and setup, and source documents showing the actual transaction. For facility users, verify facility assignment and LGA. Use a supported modern browser with local storage enabled.

Use each participant's named live account. Use separate browser profiles for the facilitator's MDA, Viewer and Admin accounts. The current offline outbox is browser-wide; do not switch accounts while submissions are pending. Seed/demo accounts and shared passwords are not the onboarding login procedure. Viewers inspect and comment on live submissions; they do not use Imports or approve transactions.

## Funding field guide

Open **Funding → New funding entry** (`/funding/new`). Check the default date before saving: use the actual July-September receipt date, not the October onboarding date.

| Field | Required | Meaning and rule |
| --- | --- | --- |
| Transaction date | Yes | Actual date funds were received. Enter a valid calendar date. |
| MDA | Yes | Select an MDA for which you have funding submission permission. A single assignment may be preselected. |
| Programme Area | Yes | Select the active programme classification. |
| Funding Source | Yes | Select the source of the money received, such as a government release, BHCPF or donor funding. |
| Amount | Yes | Nigerian naira, greater than zero. Use at most two decimal places. Commas are accepted by the form. |
| Reference Number | Yes | Actual source reference. Must be unique for this MDA and fiscal year within the funding ledger. |
| Remarks | Conditional | Optional unless Programme Area or Funding Source is Other. Explain any Other selection. |
| Fiscal year and quarter | Automatic | Derived from the transaction date; do not enter the year of today's data-entry session. |
| Entry ID, author and timestamp | Automatic | Created by the system. Keep the public entry ID for follow-up. |

Do not record an approved budget or a promised allocation as money received. Record receipts supported by the source, using the actual receipt date and reference.

## Expenditure field guide

Open **Expenditure → New expenditure entry** (`/expenditure/new`). Use the actual July-September payment date and check that the derived period is FY2026 Q3.

| Field | Required | Meaning and rule |
| --- | --- | --- |
| Transaction date | Yes | Actual date the expenditure was paid. |
| MDA | Yes | Must have expenditure submission permission; facility users use their reporting MDA. |
| Money Amount | Yes | Total spent in naira, greater than zero. Use at most two decimal places. |
| Voucher Reference Number | Yes | Actual payment/voucher reference, unique for this MDA and fiscal year within the expenditure ledger. |
| Funding source breakdown | Yes | At least one actual funding source and positive allocation. Each source appears once; all allocations must equal the expenditure amount. The legacy Unspecified source is not allowed for new manual entries. |
| Payment Method | Yes | Select the method actually used: the configured bank transfer, cheque, cash, GIFMIS, IPPIS or Other option. |
| Programme Area | Yes | Select the relevant programme classification. |
| Expenditure Category | Yes | Select the spending category. A selected state-budget item can set and lock this classification. |
| Approved Budget Item | Optional linkage | Appears when a funding allocation uses the state-budget source. Select a matching MDA/year/class line where applicable. The current validator does not make this universally mandatory. |
| Expenditure Item | Optional | For non-state-budget classification, choose a configured item consistent with the selected category. |
| AOP Activity | Optional | If linked, must belong to the same MDA and fiscal year. |
| PHC status, LGA and Facility | Conditional | PHC expenditure requires an LGA and PHC-classified facility in that LGA. The current route exposes location controls for assigned Facility Users, not ordinary MDA/Admin entry. |
| Remarks | Conditional | Required when Programme Area, Expenditure Category or Payment Method is Other. |
| Voucher attachment | Not ready for training | The UI accepts one image/PDF up to 10 MiB, but the route currently ignores the file argument. Do not promise that choosing a file saves it. |
| Fiscal year, quarter, entry ID, author and timestamp | Automatic | Derived or recorded by the system. |

Use the actual source allocation documented for the payment. All allocated amounts must equal the expenditure total. Splitting funding does not create two expenditure transactions. A single-source allocation follows the total amount automatically in the form. Payments funded from several sources should use this manual form; the current importer supports one funding source per expenditure row.

Zero activity should not be entered as a zero-value transaction: both transaction forms require amounts greater than zero. Separately imported monthly tracking data distinguishes an explicit zero return from a missing return.

## Corrections, comments and missing dropdowns

1. Find the entry in Funding, Expenditure or the entry register. Confirm MDA, period, reference and amount.
2. Read comments and audit history. A Viewer should ask a specific, genuine question, for example: “Please confirm this payment date against the source voucher.” Do not add dummy comments to live records.
3. The author can correct their own entry while the quarter remains unpublished and their submission grant is valid. Admin corrections require an audit reason.
4. If a needed dropdown value is absent, use Reference Requests. Do not choose an unrelated value to get past validation. Use Other only when it fits and explain it.
5. For a published quarter, escalate to the Admin's BIR amendment workflow. Comments do not unlock it. Offline capture does not override the lock at sync time.

## Admin planning data

Approved Budget forms require fiscal year, MDA, personnel, other recurrent and capital amounts. Amounts can be zero but cannot be negative. Recurrent and overall totals are calculated. The MDA/year combination is unique; an optional source label provides context.

AOP Activity forms require fiscal year, owning MDA, activity code, description and a non-negative budgeted cost. Source-row identity preserves legitimate repeated activity codes. Optional planning metadata depends on the configured form. Approved budgets and AOP costs describe plans; neither is evidence that cash was received or spent.

Reference data includes MDAs and their types, programme areas, funding sources, expenditure categories/items, payment methods, LGAs and facilities. During onboarding, create or update only genuinely required, verified reference values. Deactivate obsolete values to preserve history. Explain BIR publication using the screen and existing records; publish only when the real Q3 reporting process is complete and authorized.

## Import real Q3 transactions

The current importer supports **UTF-8 CSV and XLSX, up to 10 MB and 5,000 data rows in the selected table**. Each batch imports one sheet/table of individual funding or expenditure transactions. A workbook may contain several sheets, but the user chooses one for the batch. Keep an unchanged original and prepare a working copy containing only the intended Q3 transaction data.

1. Open **Imports**, choose whether rows record Funding or Expenditure, select the file and press **Upload and inspect**. Uploading creates a private draft; it does not insert ledger records.
2. For a workbook, review **Workbook sheets** and select **Use this sheet** for the actual transaction table. Do not choose a dashboard, lookup, budget, monthly return or quarterly summary.
3. In **Map columns**, verify every suggested mapping against the sample values. If the file has no MDA column, select one permitted MDA only when every row belongs to it. Choose day-first or month-first interpretation for numeric dates based on the source. ISO dates such as 2026-07-15 avoid this ambiguity. Press **Apply and check rows** after changes.
4. Inspect **Ready**, **Blocked**, **Skipped**, **Excluded** and **All**. Correct genuine source errors using the row edit control and **Save and re-check**, or exclude unresolved/out-of-scope rows. A missing whole column must be added to the working file and mapped; do not invent values. Corrections in the preview preserve the uploaded original.
5. Check **Ready rows by quarter**: every included row for this exercise must be **2026 Q3**. The importer can accept other open quarters; it does not automatically restrict this session to Q3. Exclude accidental Q1/Q2/Q4 rows and verify Ready rows by MDA.
6. Reconcile the ready count and amount with the source records selected for insertion. Review hidden-row/formula warnings against the original. Acknowledge warnings only when the values are verified.
7. The submitter presses **Insert [count] funding/expenditure entries totalling [amount]** only when the displayed set is correct. Confirmation inserts ready rows into the live database and makes them reportable immediately. Blocked/skipped/excluded rows are not inserted. Their presence does not necessarily prevent confirmation of ready rows, so explicitly record any partial submission.
8. Read the receipt's committed count, amount and public entry IDs. Download **Issue report** and assign an owner to each unresolved row. Find the saved entries in the register and let the Viewer inspect them. A completed batch is immutable; remaining unresolved rows need a corrected follow-up file containing only outstanding transactions.

Funding imports require date, MDA (or a confirmed whole-file MDA), programme area, amount, funding source and reference number. Expenditure imports additionally require expenditure category, payment method and voucher reference, with one actual funding source covering the entire amount. Optional mappings include remarks, expenditure item, AOP code and PHC LGA/facility. The import mapping does not currently offer Approved Budget Item linkage; use the manual workflow when that linkage or split funding is needed.

An existing reference with the same date and amount can be skipped as already recorded. Compare its other details in the register as well; skip detection is not a full-field reconciliation. A reference with conflicting date/amount is blocked and never silently overwrites the entry. Use the normal correction workflow rather than assigning a new reference to the same transaction.

If a file is damaged, unreadable, too large or in an unsupported format, use its error message to prepare a valid copy and upload again. For amounts in thousands/millions, convert verified values to naira and use an unambiguous header. Formulas with missing saved results require recalculation and saving in Excel. The importer does not invent missing references, sources or dates and does not automatically repair every corrupted file.

PDFs and the earlier multi-MDA budget tracking workbooks may contain aggregate returns rather than individual transactions. Use them as evidence for reconciliation or route them to the Admin's appropriate data-loading process. Do not reshape a quarter total into an invented voucher just to use Imports.

## Suggested live working session

| Minutes | Topic | Exercise or outcome |
| --- | --- | --- |
| 0-15 | Live account and Q3 readiness | Confirm role/grants, Q3 publication state, source ownership and starting records/totals. |
| 15-30 | Date and data classification | Distinguish budgets, receipts, payments and aggregate returns; select actual July-September documents. |
| 30-50 | Guided manual entry | Enter one real, previously unrecorded receipt/payment per relevant participant. Verify actual date/reference and source allocations. |
| 50-85 | Import working session | Upload real Q3 CSV/XLSX transactions; map columns, resolve issues, reconcile the preview, confirm and retain the receipt. |
| 85-100 | Offline capture | With the responsible MDA submitter, capture one genuine outstanding Q3 transaction offline and verify its later synchronization. |
| 100-120 | Viewer checks and MDA reconciliation | Compare source and register, record unresolved rows and agree owners/follow-up. Admin resolves real access/reference issues. |

Allow additional working time for large registers. Completion is determined by reconciliation, not the two-hour slot ending. Never manufacture a receipt, payment, warning or comment for demonstration. If a participant has no unrecorded transaction, they can review existing records or watch a colleague's authorized entry.

## Completion and reconciliation for each MDA

Record MDA, submitter, source filename/register and version, starting Q3 counts/totals, new manual entry IDs, import batch receipts, and final Q3 counts/totals separately for Funding and Expenditure. Identify existing source records rather than assuming every upload row is new.

Account for every intended Q3 transaction as: already recorded and checked; newly saved manually; inserted by a confirmed import; or outstanding with a stated issue and owner. Rows excluded for belonging to another period/MDA should be listed separately. Reconcile by July, August and September as well as the quarter where source detail allows. Explain differences instead of adjusting figures to force agreement.

Download issue reports before closing completed batches. Assign missing references, ambiguous sources, unmatched classifications, possible aggregate overlaps and locked-period issues to a named person with a follow-up date. A partially imported file is not a completed MDA return.

Viewers check dates, references, classifications, allocations and source totals and leave genuine comments. This is a reconciliation check, not a software approval step. Admins handle access/reference issues and audited corrections. Retain supporting documents in the MDA's normal records process; a chosen voucher file is not proof of saved attachment.

Before leaving, confirm no pending offline entries remain unnoticed. Retain failed entries and error details for resolution; do not clear browser storage. Keep verified live submissions in the database. There is no post-training wipe or demo-data cleanup for these real Q3 records.

## Facilitator FAQ

- **Why is Funding or Expenditure missing?** Check the relevant MDA grant, not just the role name.
- **Is a comment an approval?** No. Valid server submissions are already reportable.
- **Why is my saved offline row absent from reports?** It must sync successfully first; then reload the relevant list/report.
- **Why does an empty quarter show MDA reporting gaps?** A gap view can enumerate MDAs that have no returns. That is not evidence of transactions in that quarter.
- **Can I upload Excel today?** Yes, through Imports for CSV/XLSX transaction tables. Follow the mapping, review, confirmation and receipt steps above.
- **Is the importer AI-powered and can it read PDFs?** AI help is optional: **Analyze sheets with AI**, **Suggest mapping with AI** and **Suggest answers with AI** send column names, up to 8 sample rows or unmatched values to OpenAI and return suggestions you confirm. Validation and insertion stay deterministic. PDFs are not accepted yet.
- **Should I use today's date?** Only if that is the actual transaction date. This exercise is Q3 2026, so included receipts/payments must be dated 1 July through 30 September.
- **Can I import split-source payments?** Use the manual expenditure form for those; do not duplicate the voucher into separate imported rows.
- **Can I use the quarterly total as one transaction?** Only transaction evidence belongs in the transaction form. Period summaries must follow the appropriate aggregate data path.
- **Does a selected voucher file mean it was saved?** Not in this version. Attachment persistence needs implementation and verification.
- **Can we sign in for the first time offline?** No. Complete sign-in and load permissions/reference data online first.
